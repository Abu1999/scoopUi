# ScoopUI M5a 配置集设计

日期：2026-09-23
状态：已确认（用户批准）
上游：`docs/superpowers/specs/2026-09-17-scoopui-design.md` §4.6（配置集）、§4.1（多根/全局）、§5（页面结构）
里程碑：M5a（配置集）；M5b（备份/恢复）另行设计

## 1. 目标与范围

为 ScoopUI 增加配置集（Profile）：把「一组桶 + 一组应用 + 一组下载加速设置」保存为可复用文件，并可在任意已选根目录上一键应用（差集加桶、安装缺失应用、写入白名单设置），支持导入 `scoop export` 原生 JSON、导出自家格式、重命名与删除。

同时按已确认决策把**全局应用（SCOOP_GLOBAL）**纳入管理：已安装列表与更新检测覆盖全局应用并标注。

### 已确认决策（用户问答结论）

1. M5 拆分为 M5a（配置集）与 M5b（备份/恢复），先做 M5a。
2. 应用配置集默认执行：加桶（差集）+ 安装缺失应用 + 应用 settings；「卸载多余应用」为默认关闭的开关。
3. 完整支持全局应用，落地范围为：已安装页展示与操作 + 更新检测全覆盖。
4. 创建/导入/导出能力：另存当前状态、导入（自动识别自家与 scoop export 两种格式）、导出自家 JSON；不做界面内 JSON 编辑。
5. settings 仅覆盖下载加速白名单键：`url_proxy`、`proxy`、`aria2-enabled`、`aria2-split`、`aria2-max-connection-per-server`。
6. 应用执行方式：逐条串行、失败即停，剩余步骤标记「待执行」，重跑自动跳过已完成项。
7. 配置集页布局：左列表 + 右详情（含差异对比区）。
8. 桶信息保留可选 source：`buckets: [{name, source?}]`，导入兼容纯字符串数组。

### 非目标（本期不做）

- 自动快照/回滚（M5b 的备份能力；M5b 可加「应用前快照」）
- 应用时自动变更已存在桶的 remote（仅提示源冲突）
- 应用时删除当前多出的桶（仅提示）
- 全局应用的安装需管理员权限：沿用既有提示路径，不自动提权
- 界面内编辑配置集 JSON

## 2. 数据模型与存储

### 2.1 存储位置与命名

- 目录：`%APPDATA%\scoopui\profiles\`（`paths::profiles_dir(appdata) = settings_dir(appdata).join("profiles")`）
- 一个配置集一个文件：`<name>.json`，文件名即配置集名
- 名称校验（`validate_profile_name`）：
  - 去除首尾空白后非空，且必须等于原名（拒绝首尾空白）
  - 不等于 `.` 或 `..`，不以 `.` 结尾
  - 不含 `\ / : * ? " < > |` 与控制字符
  - 与桶名校验同模式；允许空格与中文（但首尾空格拒绝）

### 2.2 Profile JSON（自家格式，version 1）

```json
{
  "version": 1,
  "name": "工作",
  "created": 1758614400,
  "buckets": [{ "name": "main", "source": "https://github.com/ScoopInstaller/Main" }],
  "apps": [{ "name": "git", "bucket": "main", "global": false }],
  "settings": { "url_proxy": "https://scoop.201704.xyz" }
}
```

字段规则：

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | u32 | 固定 1；读取时不校验高版本（未来演进预留） |
| `name` | string | 必须与文件名一致；导入时由前端传入的名称覆盖 |
| `created` | u64 | Unix 秒（不引入时间库；前端 `new Date(created*1000)` 本地化展示） |
| `buckets[].name` | string | 桶名 |
| `buckets[].source` | string? | git 远程地址；仅保留远程 URL（`http://`/`https://`/`git@`/`ssh://` 前缀），本地路径等一律置 null |
| `apps[].name` | string | 应用名 |
| `apps[].bucket` | string? | 来源桶名；`<auto-generated>`、URL、空串 → null |
| `apps[].global` | bool | 默认 false |
| `settings` | object | 仅白名单键，见 §2.3 |

导入兼容：`buckets` 元素允许纯字符串（等价 `{name, source: null}`）。

### 2.3 settings 白名单与类型

| 键 | 类型 | 校验 |
|---|---|---|
| `url_proxy` | string | 字符串，非空 |
| `proxy` | string | 字符串，非空 |
| `aria2-enabled` | bool | 布尔 |
| `aria2-split` | number | 非负整数 |
| `aria2-max-connection-per-server` | number | 非负整数 |

- 另存时：从当前生效 config 读取存在且类型合法的白名单键
- 应用时：只写配置集中**存在**的键；不删除当前 config 中多出的键
- 类型不符的键：报错 `settings.{key} 类型不符`，整体不写

## 3. 后端设计

### 3.1 新增 `src-tauri/src/domain/profiles.rs`

```rust
pub const SETTINGS_WHITELIST: [&str; 5] = [
    "url_proxy", "proxy", "aria2-enabled", "aria2-split", "aria2-max-connection-per-server",
];

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct BucketRef { pub name: String, pub source: Option<String> }

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ProfileApp {
    pub name: String,
    pub bucket: Option<String>,
    #[serde(default)]
    pub global: bool,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Profile {
    #[serde(default = "default_version")]
    pub version: u32,
    pub name: String,
    #[serde(default)]
    pub created: u64,
    #[serde(default, deserialize_with = "de_buckets")]
    pub buckets: Vec<BucketRef>,
    #[serde(default)]
    pub apps: Vec<ProfileApp>,
    #[serde(default)]
    pub settings: serde_json::Map<String, serde_json::Value>,
}

#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct ProfileSummary {
    pub name: String,
    pub created: u64,
    pub bucket_count: usize,
    pub app_count: usize,
    pub settings_count: usize,
}

#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct SettingDiff { pub key: String, pub current: Option<serde_json::Value>, pub target: serde_json::Value }

#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct ProfileDiff {
    pub missing_buckets: Vec<BucketRef>,
    pub extra_buckets: Vec<String>,
    pub bucket_source_conflicts: Vec<String>,
    pub missing_apps: Vec<ProfileApp>,
    pub extra_apps: Vec<ProfileApp>,
    pub settings: Vec<SettingDiff>,
}
```

说明：`default_version` 返回 1；`de_buckets` 为自定义反序列化，接受 `Vec<BucketRefRaw>`（`#[serde(untagged)] enum BucketRefRaw { Name(String), Full(BucketRef) }`）并映射为 `Vec<BucketRef>`，兼容 `["main"]` 与 `[{name, source}]` 混写；序列化统一输出对象形式。

函数：

| 函数 | 行为 |
|---|---|
| `validate_profile_name(name: &str) -> Result<(), AppError>` | §2.1 规则；错误消息 `配置集名称非法: {name}` |
| `list(dir: &Path) -> Vec<ProfileSummary>` | 读取目录下 `*.json`；解析失败的文件跳过（不阻断列表）；按名称不区分大小写排序 |
| `load(dir: &Path, name: &str) -> Result<Profile, AppError>` | 名称校验后读 `<dir>/<name>.json`；不存在报 `配置集不存在: {name}`；解析失败报 `配置集文件损坏: {name}` |
| `save(dir: &Path, profile: &Profile) -> Result<(), AppError>` | 名称校验 + `create_dir_all` + 写 `*.json.tmp` + rename（原子写，模式与 `settings.rs` 一致） |
| `delete(dir: &Path, name: &str) -> Result<(), AppError>` | 名称校验后删除文件；不存在报 `配置集不存在: {name}` |
| `rename(dir: &Path, name: &str, new_name: &str) -> Result<(), AppError>` | 双方校验；新名已存在报错；读取→改 `name`→写新文件→删旧文件 |
| `snapshot(name: &str, buckets: &[BucketInfo], apps: &[InstalledApp], config: &Value) -> Profile` | 组装当前状态：桶（含 source）+ 应用（含 global）+ config 白名单键 + `created = now_epoch()` |
| `parse_import(text: &str, name: &str) -> Result<Profile, AppError>` | 自动识别两种格式（§3.2） |
| `diff(profile: &Profile, buckets: &[BucketInfo], apps: &[InstalledApp], config: &Value) -> ProfileDiff` | §3.3 |
| `apply_settings(config_path: &Path, settings: &Map<String, Value>) -> Result<(), AppError>` | 白名单过滤 + 类型校验 + 逐键 `configfile::set_key` |
| `now_epoch() -> u64` | `SystemTime::now().duration_since(UNIX_EPOCH)` 秒，失败回 0 |

### 3.2 导入格式识别（`parse_import`）

1. 先尝试自家格式：`serde_json::from_str::<Profile>` 成功且顶层 `name` 存在 → 覆盖 `name` 为传入值后返回。
2. 否则尝试 scoop export 格式：

```rust
#[derive(Deserialize)]
struct ScoopExport {
    #[serde(default)] buckets: Vec<ScoopBucket>,
    #[serde(default)] apps: Vec<ScoopApp>,
    #[serde(default)] config: serde_json::Map<String, serde_json::Value>,
}
#[derive(Deserialize)]
struct ScoopBucket { #[serde(rename = "Name")] name: String, #[serde(rename = "Source", default)] source: Option<String> }
#[derive(Deserialize)]
struct ScoopApp {
    #[serde(rename = "Name")] name: String,
    #[serde(rename = "Source", default)] source: Option<String>,
    #[serde(rename = "Info", default)] info: Option<String>,
}
```

转换规则：

- `buckets[].source`：仅当以 `http://`/`https://`/`git@`/`ssh://` 开头时保留，否则 null
- `apps[].bucket`：`Source` 为 `<auto-generated>`、含 `://`、空串或缺失 → null；否则取原值
- `apps[].global`：`Info` 以 `, ` 分词后包含 `Global install`
- `settings`：`config` 中白名单键（类型校验同 §2.3，非法键忽略）
- `version = 1`、`created = now_epoch()`、`name = 传入值`
3. 两种都不匹配 → `AppError::Other("无法识别的配置集文件")`

### 3.3 差异计算（`diff`）

| 输出 | 规则 |
|---|---|
| `missing_buckets` | profile 桶名不在当前桶列表（不区分大小写） |
| `extra_buckets` | 当前桶名不在 profile（仅提示） |
| `bucket_source_conflicts` | 同名桶双方 source 均存在且归一化后不同；归一化 = 小写 + 去尾 `/` + 去尾 `.git` |
| `missing_apps` | profile 的 `(name 小写, global)` 不在当前已装应用（含全局） |
| `extra_apps` | 当前已装应用的 `(name 小写, global)` 不在 profile |
| `settings` | 白名单键中 profile 有值且与当前 config 不同（当前缺失或值不同）；按白名单顺序输出 |

排序：`missing_buckets`/`extra_buckets` 按名称小写排序；`missing_apps`/`extra_apps` 按名称小写排序（同名 local 在前）。

## 5. 应用流程（前端编排）

应用按钮 → `profile_diff` → 确认弹窗（差异摘要 + 「同时卸载多余应用」开关，默认关）→ 生成步骤清单 → 逐条串行执行。

步骤顺序（固定）：先 settings 再安装，使 `url_proxy` 在后续下载前生效。

1. **settings**（若差异非空）：一条 `apply_profile_settings(profile.settings)`
2. **缺失桶**：每个一条 `bucket_add(name, source)`（source 为空传 null，走 scoop 已知桶名）
3. **缺失应用**：每个一条 `install_package(name, bucket, null, global, taskId)`
4. **多余应用**（仅开关开启）：每个一条 `uninstall_package(name, global, false, taskId)`

执行语义：

- 每步用 `runTask` 执行，`ui.logDrawerOpen = true`；步骤状态：`pending | running | success | failed | skipped`
- 任一步失败：该步 `failed`，后续 `skipped`，停止执行；弹窗保留并展示失败步骤，提供「重新计算并重试」
- 全部成功：刷新 `apps`/`buckets` store，关闭弹窗并 `message.success`
- 重试：重新 `profile_diff` 生成清单（已完成项自然消失）

## 7. 错误处理

- 名称非法/重复：命令返回中文错误，页面 `message.error` 展示
- 配置文件损坏：`load` 报「配置集文件损坏」，列表仍可用（跳过损坏文件）
- 导入无法识别：报「无法识别的配置集文件」
- 应用失败：失败步骤红标 + 剩余「待执行」；日志抽屉可见完整输出；不自动回滚已完成步骤
- `global_dir` 不可解析：全局应用视为空集合，不报错
- settings 类型不符：`apply_profile_settings` 整体拒绝并报具体键

  - `diff`：缺失/多余桶、源冲突（尾斜杠/`.git`/大小写归一化）、缺失/多余应用（含全局同名区分）、settings 仅变化项
  - `apply_settings`：只写白名单、类型不符报错、不删多余键
  - `save/load/delete/rename`（tempdir）、损坏文件跳过列表、重名报错
- `domain/installed.rs`：`scan(_, true)` 标记 global；`scan(_, false)` 不标记
- `domain/updates.rs`：`UpdateInfo.global` 透传
- `paths.rs`：`profiles_dir` 拼接正确

## 9. 已知取舍与风险

- 取舍：`created` 用 Unix 秒（不引入时间库），展示本地化在前端完成
- 取舍：应用不修改已存在桶的 remote、不删除多余桶（避免破坏性操作）
- 取舍：settings 不删除当前多余键（非破坏性）
- 取舍：应用失败不回滚；重跑靠 diff 幂等
- 风险：同名应用本地+全局同时存在时，已安装页以 `appKey` 区分，UI 需清晰标注全局，避免误操作
- 风险：`scoop bucket add <name>`（无 source）依赖 scoop 已知桶列表，不在列表的桶会失败并如实提示
- 风险：全局应用安装需要管理员权限；失败信息来自 scoop 输出，沿用既有错误提示路径
